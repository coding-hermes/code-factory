## 2. Purpose, authority and position

Gives the node the right tree and gives finished work its path into `origin/main`
(`land-node-branch.sh`). It decides what a landing may publish (an explicit
`<merge_sha>:refs/heads/<main>`, never `HEAD`), what the gate may allow, and when a clone is too
stale. It may not decide what work is *worth* landing — that is the foreman/board (M4).

**What breaks if this module is absent.** The node has no right tree and work cannot leave it.
`land-node-branch.sh` is the landing path for a finished node task — the result envelope names
`branch` and `commit` (`node-bus-worker.py:1187-1188`) and this script is what an operator (or an
out-of-repo foreman step) runs with `--branch/--commit` to merge them. **Nothing in-repo invokes it**
(F3-5): `grep -rn 'land-node-branch' scripts/ tests/` matches the script itself (`scripts/land-node-branch.sh:2,4,120`) and the selftest arm (`tests/selftest.sh:2464,2470,2471,2472,2478,2507,2730` — the BEGIN banner, the `bash -n` syntax arm, and the `cf213` usage arm). The envelope *names* the fields; it does
not *call* the lander. M3 owns F5 LANDING, a primary flow — but the landing step is operator-triggered.

**What breaks if it lies.** A landing that reports success without the commit actually in
`origin/main` is the exact defect the script is built to refuse: it pushes an explicit object,
re-fetches, and proves `git merge-base --is-ancestor` (`:278-300`). The PASS row belongs to the
proof, never to the merge (`:23`).

## 11. Limits and margins

- The landing script refuses, naming the measured value, before merging anything (`:11-20`).
- The gate runs in a detached worktree at the node's commit so it measures the node's tree, not
  main's (`:60`, `:175-191`).
- **Hook effectiveness is not proven by hook presence (B11, read).**
  `install-gitreins.sh:59-63` checks only that `.git/hooks/pre-commit` is executable and contains
  the string `gitreins`; `:120-138` writes a hook whose first act is `exit 0` when
  `.gitreins/config.yaml` is absent (`:130-131`). It does **not** resolve the effective
  `core.hooksPath`, and a generated hook file does not prove git invokes it. A disposable
  rejecting-commit fixture is the missing evidence; none is shipped.
