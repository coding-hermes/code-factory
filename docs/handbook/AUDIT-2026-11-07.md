## W6 RESOLUTION (2026-11-07, CF2A-01-w6.pdf, 156 pp — all four fixed, build green)
- R1 root cause (audited hypothesis was wrong): block order inside pages was always
  correct; the PAGE order inverted. The splitter peeled trailing blocks off the end and
  inserted each at the top of one continuation div — order-safe only while everything
  fit on that ONE continuation. When the continuation itself overflowed, the reopen
  path opened yet another page and kept peeling into it: page k+1 always received
  content EARLIER than page k, so every multi-page split imposed in reverse. Fix:
  build_book.py's PAGINATE_JS rewritten as forward assembly — walk content in reading
  order, cut at the first block (or first non-fitting table row) that crosses the page
  budget, carry the cut onward; page sequence = reading order by construction. Proven
  by hashing the pre- and post-pagination content streams (every body row + block) in
  a live browser: identical.
- R2 same code: a continuation table opened for one table could inherit rows from a
  different one (`np._tb` stayed open across tables). Gone with the rewrite: each
  continuation is opened per table, carries that table's own thead clone, and every
  placard is welded to its own rows.
- R3 header-only frames became unreachable: a cut that would leave a source table with
  zero body rows moves the whole table instead; emptied continuation frames are
  dismantled. Mechanical check across all 156 pages: zero header-only frames at any
  page foot, zero stranded placards.
- R4 M3's gitleaks quotes kept verbatim and annotated (`~` is gitleaks' approximately
  marker — "never negative" / "approximately zero bytes scanned" on the M3 §7 rows).
- Gates: lint clean · dochead + folio on every page · fit clean (build OK line).
  Page count 184 → 156 (the old splitter padded mostly-empty continuation sheets).
