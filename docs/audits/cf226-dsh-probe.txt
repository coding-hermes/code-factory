What this is: the measured evidence behind `scripts/harness/install-dsh.sh` — a pinned
install of npm `@deepseek-ai/dsh` 0.2.1-rc.5 (an RC), one real turn, the per-layer
diagnosis, the credential refusals, and the RC re-measurement. Nothing below is composed
from memory: each block is the output of the command named above it, on the control host,
2026-11-08/09 (node 22.22.3, npm 10.9.8, Linux x86_64).

Absolutely no credential VALUE appears in this file: a key is only ever named as a PATH,
and the turn's key file is read inside the child shell. `$HOME` is rendered as `~`.

Sections

     (captured by `CF_DSH_TEST_APPLY=1 tests/harness/dsh-install-test.sh`; the scratch tree
     held no prior dsh state, so the `provenance` and `install` rows are a real download)
  2. --check on the control host after that install
  3. --pin-status — how an RC pin is re-measured from the registry
  4. --layers with a credential — all six layers measured
  5. --turn — one real turn, its artifact, and the model dsh recorded
  6. Refusals — a credential VALUE, and an ambient DEEPSEEK_API_KEY

What this does NOT prove: that a crier adapter exists (it does not; the decision is recorded
in specs/HARNESS.md §"dsh — the adapter decision"), that the DuckBrain `memory` leg is
written (the foreman owns it), or that this ladder installs on a node without node ≥ 22 —
the pin declares no `engines` field, so a lower major is reported as unmeasured, not refused.
