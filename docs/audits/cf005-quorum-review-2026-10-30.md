## Reproduced findings

1. **False-positive red control.** `tests/selftest.sh:13-16` runs `project-node.sh --check` with `PATH=/nonexistent`, then accepts any output containing the substring `FAIL`. Reproduction in a clean environment returned exit 1 but failed during bootstrap (`dirname`, `cd`, missing `/lib.sh`, missing commands) and ended with `FAILED: unbound variable`. The substring check therefore passes without a named node-check failure. Preserve bootstrap tools, trigger one intentional check failure, and assert an anchored `FAIL <named_check>` row.
2. **Provider-key policy conflict.** `scripts/harness/install-hermes.sh:90-94` makes a node-side `~/.hermes/.env` provider-key assignment a PASS prerequisite. `CF-002` acceptance criterion 2 explicitly requires that node file, while the owner’s standing constraint is provider keys stay on the control host and no key is copied to a node without authorization. README says the node needs its own credential but never an operator key (`README.md:84-85`). No key was copied and no node was provisioned. Amend CF-002 to specify a host-side inference gateway/proxy and node-scoped service identity, with no provider key on the node; keep live execution blocked until that path is implemented and authorized.
3. **Missing repo precondition.** `scripts/node-create.sh:26` checks only `PROJECT` before it can spawn an agent (`:34-39`); `REPO` may be empty despite the usage contract. A fake-Bunker probe accepted the project+harness-only request and reported creation. Reject missing/invalid repo before any spawn and assert no spawn call.
4. **Artifact path overreach.** `scripts/verify-node.sh:61-66` allows general paths in a shell-character allowlist and interpolates the path into remote `bash -lc` commands. A stub accepted `--artifact ~/.hermes/.env` and reported a digest; this did not read a real credential file. Restrict verification to a dispatch-scoped artifact/manifest path and test denial of credential/config paths.
5. **Manifest failure and reuse.** `scripts/project-node.sh:134-151` preserves an existing manifest without checking that project/repo/harness match the requested identity. On first write, the Python writer’s exit status is not checked before `ok "manifest"` is emitted. Fail closed on write errors and reject identity mismatch on re-apply.
6. **Spec/threat-model drift.** `docs/THREAT-MODEL.md:47` says missing auth is WARN while `scripts/verify-node.sh:45-47` calls `bad`; the threat-model table also describes shell/artifact boundaries contradicted by the current `%q` provisioning command and verifier behavior. `specs/NODE.md:29` lists a Crier pull worker, while `:53-55` says no worker is shipped; `:79` promises dirty-repo warning behavior not implemented in `project-node.sh`. Reconcile each claim to measured source behavior or clearly mark it unimplemented.
