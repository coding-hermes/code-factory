FIX — scripts/harness/install-hermes.sh (388 lines, +13)
-------------------------------------------------------
One gate, one parser: the occupied-port branch now calls check_public_bind_auth — the same shell
function (same strict YAML subset, same refusal reasons) the --apply start path already uses; no
second parser was written and node_gateway_auth.py was not touched (it is the WRITER, not the
validator, and its messages are pinned by other arms).

    if (command -v ss >/dev/null && ss -tln 2>/dev/null | grep -q ":$PORT ") 2>/dev/null; then
      if port_auth_reason=$(check_public_bind_auth); then
        ok "port" "listening on :$PORT"
        code=$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 ".../api/status" ...)
        [ "$code" = 200 ] && ok "status_probe" "/api/status -> 200" || bad "status_probe" "/api/status -> $code"
      else
        bad "port" "listening on :$PORT (not started by this adapter; auth unverified — a public bind needs dashboard.basic_auth in ~/.hermes/config.yaml — ${port_auth_reason:-block absent (config check failed)})"
      fi
    else
      ... unchanged (the CF-071 refusal and the --apply start path are untouched) ...

The FAIL row is counted by bad(), so the layer line is truthful (`HERMES: FAIL (n)`, exit 1). The
NOT-listening branch, the CF-071 refusal wording and the status_probe/LISTENING PASS rows for an
authenticated port are byte-identical to before.
